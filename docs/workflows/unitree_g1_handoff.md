## 低层全身控制集成计划

目标：在关闭机载ai_sport的原调试模式下，由本地控制器持续维持下半身站立和平衡，同时保留Quest双臂遥控、内走线Dex1和三路采集，最终恢复有明确动作语义的16维训练数据。此路线替代的是下半身控制实现，不是把机内ai_sport通过SDK调用搬到本机。

候选基础为宇树官方开源[unitree_rl_gym](https://github.com/unitreerobotics/unitree_rl_gym)，包含G1预训练策略`deploy/pre_train/g1/motion.pt`、[真机部署程序](https://github.com/unitreerobotics/unitree_rl_gym/blob/main/deploy/deploy_real/deploy_real.py)及[G1配置](https://github.com/unitreerobotics/unitree_rl_gym/blob/main/deploy/deploy_real/configs/g1.yaml)。它支持调试模式和`rt/lowcmd`，但不能视为机内ai_sport的同一实现或同等性能保证。正式集成前固定源码提交、模型哈希和依赖版本；普通SDK低层示例的姿态插值/踝关节摆动不构成平衡控制器。

控制分工拟定如下，所有目标由同一个执行层合并，唯一DDS发布器发送完整LowCmd；禁止并行启动原部署示例与现有Quest发布器。

| 电机槽位 | 计划控制来源 |
| --- | --- |
| 腿部0–11 | 下半身策略输出12维关节目标，按策略要求处理观测、缩放、默认姿态及PD参数 |
| 腰部12–14 | 由下半身控制器统一管理，初期明确姿态保持策略，不与上肢争用 |
| 双臂15–28 | 现有Quest IK及速度/加速度受限执行层，替换官方部署示例的固定手臂目标 |
| 内走线Dex1左31/右33 | 现有扳机位置控制、预全开及闭合冻结逻辑，纳入同一发布器 |

主要适配与验证问题：

- 官方候选配置为12维动作、47维观测，控制周期0.02秒；观测含步态相位，但没有手臂关节状态，部署示例将腰臂保持在固定目标。零移动速度指令不等于已验证的双脚静止站立，先验证是否踏步、漂移及能否抗扰。
- 双臂伸展、加减速、夹爪及抓取负载会改变重心和动力学。对照本机G1 EDU+的自由度、质量/惯量、IMU坐标系和关节映射，先验证现有策略；若不足，再设计包含上肢姿态变化、动作扰动和物体负载的训练或微调，不承诺原预训练模型可直接支持遥操抓取。
- 策略推理、全身伺服发布、Quest输入和相机写盘需分离时序，检测推理/反馈超时；Quest或采集退出不能顺带终止下半身控制循环。
- 必须重写原来的退出和故障处理：正常结束采集、松侧握键或Quest断流时，停止上肢动作并继续下半身平衡；不能沿用全身零增益尾帧。下半身策略故障、通信丢失、倾倒与独立急停另设处置和验证，不假设冻结腿部目标或零力矩能维持站立。
- 原Dex1预全开会独立使用lowcmd且令身体被动，不能原样作为新流程的前置子进程。预全开必须纳入已运行的全身控制器，使其全过程持续维持下半身控制。
- 记录发送前全身状态、IMU、策略输入/输出、最终合成指令及控制器阶段。后续16维动作继续取实际提交的双臂和夹爪目标，明确腰部/末端坐标约定；新控制路径须独立验证导出，不能沿用arm_sdk原始诊断会话作为已验收训练数据。

实施顺序与阶段出口：

1. **离线盘点与固定版本**：确认模型/配置适配本机29自由度双臂和内走线夹爪，核对全部映射、单位及策略观测；建立独立候选配置，保留现有debug和arm_sdk入口。
2. **纯下半身仿真**：在MuJoCo等仿真中验证起始姿态、零速度站立、推扰、推理延迟及异常状态；记录倾角、漂移、踏步、关节/力矩边界，制定可复现的通过标准。
3. **双臂与负载仿真**：接入实际Quest轨迹或离线动作回放，加入夹爪质量、抓取负载及左右不对称伸展；验证上肢动作、预全开及退出期间的平衡，必要时训练适配策略。
4. **统一执行层与离线回归**：实现单一LowCmd发布器及全身状态机；测试发布独占、目标合成、上下肢故障分流、输入/推理超时、采集失败、正常结束后持续站立和日志/导出语义。禁止复用旧全身卸载逻辑。
5. **有支撑的真机分阶段验证**：通过前述检查后，按当次现场授权先验证下半身，再验证小幅双臂、夹爪，最后带物采集；不以过去悬挂调试或arm_sdk离线测试替代验收。双臂配置当前为1.0 rad/s、2.0 rad/s²，但不据此宣称新平衡策略已适应该动作范围。

本计划尚无实施或真机验收结果；下一项工作从版本固定、模型适配检查及仿真开始，不直接在站立真机上拼接运行示例。
